  值得优化的地方                                                                                                                                                                                                                                     
                                                                                                                                                                                                                                                     
  1. 引用解析率只有 20.6%                                                                                                                                                                                                                            
    607 resolved / 2,949 refs                                                                                                                                                                                                                        
    exact=1061 fuzzy=375 skipped_common=1009 skipped_many=11                                                                                                                                                                                         
  跳过了 1,009 个高频名（Error, Len, String, Close 等），这合理。但 2,949 条引用跑了 3.1 秒，说明模糊匹配的回退开销不小。建议：给模糊匹配加超时，匹配不到就快速放弃。                                                                                
                                                                                                                                                                                                                                                     
  2. 状态构建 3.7 秒排第一                                                                                                                                                                                                                           
  这是 state=3659ms 阶段，做的是 COUNT(*) 类统计查询。如果每个统计是一次独立 SQL 查询，3.7 秒说明查询次数多或表大。建议：合并为一条 SELECT COUNT(*) FROM ... UNION ALL SELECT ... 批量查询，能降到 ~100ms。                                          
                                                                                                                                                                                                                                                     
  3. 清理 2 秒 = 重建索引                                                                                                                                                                                                                            
  cleanup=1965ms 最可能是 CREATE INDEX IF NOT EXISTS 或 REINDEX。建议：检查是否在每次 worker 运行时都重建了索引，如果是，改为只在首次创建时建索引。

  1. 🔴 StateBuilder — 3.7s（最大瓶颈）                                                                                                                                                                                                              
                                                                                                                                                                                                                                                     
  问题：buildModuleSummaries() 一行 SQL 做了 5 个 JOIN + LIKE '%' || name 全表扫描，然后对每行结果 prepare/step/finalize 一条 INSERT                                                                                                                 
                                                                                                                                                                                                                                                     
    // state_builder.cpp: 每个模块一行 → 一次 prepare/finalize                                                                                                                                                                                       
    while (sqlite3_step(stmt) == SQLITE_ROW) {                                                                                                                                                                                                       
        sqlite3_stmt *ins_st = nullptr;                                                                                                                                                                                                              
        sqlite3_prepare_v2(..., &ins_st, ...);  // ← 每行一次                                                                                                                                                                                        
        sqlite3_step(ins_st);                                                                                                                                                                                                                        
        sqlite3_finalize(ins_st);               // ← 每行一次                                                                                                                                                                                        
    }                                                                                                                                                                                                                                                
                                                                                                                                                                                                                                                     
  优化方案：                                                                                                                                                                                                                                         
  •buildModuleSummaries() 的 LIKE '%' || name 无法用索引 → 改为 rtrim(file_path, ...) 提取目录前缀，加索引 (project_id, file_path)                                                                                                                   
  •全量 StateBuilder 改用单个 INSERT INTO ... SELECT 批量 SQL，把 4 个独立查询 + N 轮 prepare/finalize 合并为 1-2 条 SQL                                                                                                                             
  •预估优化：3.7s → 0.3s（90% 提升）                                                                                                                                                                                                                 
                                                                                                                                                                                                                                                     
  2. 🟡 Resolver — 3.1s（命中率 20.6%）                                                                                                                                                                                                              
                                                                                                                                                                                                                                                     
  问题：2,949 条引用，只解析出 607 条。1,009 条跳过高频名，剩余大量时间花在无结果的模糊匹配上                                                                                                                                                        
                                                                                                                                                                                                                                                     
    exact=1061  fuzzy=375  skipped_common=1009  skipped_many=11                                                                                                                                                                                      
                                                                                                                                                                                                                                                     
  优化方案：                                                                                                                                                                                                                                         
  •模糊匹配（FuzzyResolver::resolve()）加超时机制，比如 5ms 上限后直接跳过                                                                                                                                                                           
  •在 entity_index 中名字匹配不到时，延迟加载 fuzzy 结果，避免为空时仍走完整 fuzzy 路径                                                                                                                                                              
  •预估优化：3.1s → 1.5s（50% 提升）                                                                                                                                                                                                                 
                                                                                                                                                                                                                                                     
  3. 🟡 Scope 分析 — 2.4s                                                                                                                                                                                                                            
                                                                                                                                                                                                                                                     
  问题：rtrim(file_path, replace(file_path, '/', 'x')) 这个 SQL 技巧无法索引，对每个 entity 做字符串操作                                                                                                                                             
                                                                                                                                                                                                                                                     
  优化方案：                                                                                                                                                                                                                                         
  •在 entity 表加一个 module_path TEXT 列，解析时直接写入，建索引 (project_id, module_path)                                                                                                                                                          
  •或用 buildGraph 中提前算好目录路径，避免 SQL 层的字符串运算                                                                                                                                                                                       
  •预估优化：2.4s → 0.5s（80% 提升）                                                                                                                                                                                                                 
                                                                                                                                                                                                                                                     
  4. 🟡 Cleanup 索引重建 — 2.0s                                                                                                                                                                                                                      
                                                                                                                                                                                                                                                     
  问题：dropQueryIndexes() + createIndexesAfterBulkLoad() 在每次 buildGraph 后重建所有索引                                                                                                                                                           
                                                                                                                                                                                                                                                     
  优化方案：                                                                                                                                                                                                                                         
  •只对 graph_edges 和 relation 表做索引重建（这两表在 bulk insert 后索引最碎片化）                                                                                                                                                                  
  •其他表（如 entity 的索引）在解析阶段插入量不大，可以不 drop                                                                                                                                                                                       
  •预估优化：2.0s → 0.5s（75% 提升）                                                                                                                                                                                                                 
                                                                                                                                                                                                                                                     
  5. 🟡 ModelEngine — 2.3s                                                                                                                                                                                                                           
                                                                                                                                                                                                                                                     
  问题：WorkflowPlugin、CapabilityPlugin、ArchitecturePlugin、ContractPlugin 各自独立跑 SQL，互不共享结果                                                                                                                                            
                                                                                                                                                                                                                                                     
  优化方案：                                                                                                                                                                                                                                         
  •插件间共享一次 entity + relation 扫描结果，避免每个插件重复查询同样的大表                                                                                                                                                                         
  •预估优化：2.3s → 1.0s（55% 提升）
